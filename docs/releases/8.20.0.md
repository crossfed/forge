# Forge 8.20.0

Forge 8.20.0 replaces reconstructed dual-target contract graphs with native
guest CMake projects. Shared C++23 module sources are configured independently
for the host and `wasm32` toolchains, while the ordinary CMake target graph is
the single source of build dependencies.

Contract Raw encoding, named action payloads and Spring/EOSIO ABI compatibility
remain unchanged. Contract SDK build orchestration, package components and the
runtime manifest schema have an explicitly approved clean break.

## Native Guest Projects

A guest product is a standalone CMake project. It directly adds shared and
guest-only libraries and builds its contract in that configuration:

```cmake
add_subdirectory(../libraries/chain/revision chain-revision)
add_subdirectory(libraries/revision)

forge_add_contract(
   product
   SOURCES entry.cpp
   LIBRARIES product_contract_revision
)
```

`forge_add_contract_library()` creates an ordinary static CMake target with a
`FILE_SET CXX_MODULES` interface and standard public/private dependencies. The
same physical `.cppm` and `.cpp` sources may be added to a native host project
and to the guest project; each toolchain compiles its own objects and module
artifacts.

`forge_add_contract_project()` remains an optional host launcher. It invokes the
standalone guest project with the Forge toolchain and exposes artifact paths to
host tests, but it does not inspect or reconstruct the guest target graph.
`SOURCE_ROOT` identifies the common product tree for shared and guest-only
sources. Guest contract-library and contract declarations are immutable after
their Forge helper returns, keeping CMake module compilation and Abigen on one
semantic compile profile.
The guest toolchain now owns the standard configuration-specific C++ flags,
passes the selected profile to Abigen and rejects directory-wide compile
customization. Host-launched Release therefore compiles and analyzes the guest
contract with the same `NDEBUG` semantics.

## Removed Contract Graph API

The following surfaces are removed without compatibility aliases:

- `find_package(Forge COMPONENTS contract_graph)`;
- `import forge.contract.graph`;
- `forge::contract::graph::read` and its descriptor types;
- host-to-guest `contract-graph.json` transport and fingerprints;
- downstream dual-target source-package materialization.

The graph component and reader were previously marked Stable. Their removal is
an approved minor-release break because preserving them would retain a second
CMake graph with different dependency semantics.

Migration is mechanical:

1. Remove the `contract_graph` package component and module import.
2. Declare ordinary native targets in the host project.
3. Add the same shared source directory to the guest project with
   `add_subdirectory`.
4. Declare guest-only libraries and the contract directly in the guest project.
5. Replace graph-reader assertions with CMake configure failures and focused
   host/guest build tests.

There is no replacement runtime graph-reader API. CMake and Clang module
dependency scanning own the actual build graph.

## Contract Manifest Schema V3

Contract manifests now use schema v3. They record:

- Forge SDK, LLVM, sysroot and profile identity;
- imported host functions and enabled WebAssembly features;
- SHA-256 values for the WASM and ABI artifacts.

Schema v3 removes `source_graph` and does not claim source verification.
Consumers must regenerate all schema v2 sidecars and accept schema v3. Forge
does not emit schema v2 as a compatibility mode.

Etherscan-style source verification is deferred to a separate attestation
layer based on a hermetic reproducible build and compiler-derived dependency
files.

## Validation

The release gate covers native and `wasm32` C++23 modules, named action ABI,
direct/helper artifact identity, multi-configuration Release forwarding,
installed SDK relocation, VM execution and the unchanged Spring/EOSIO
compatibility corpus.
