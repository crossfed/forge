# Forge 8.29.1

Forge 8.29.1 is the compatible patch release from `v8.29.0`
(`4e0e13854f0b`) through `dev` (`d0a3c141f3bc`). It fixes Linux C++23 module
portability, standardizes X.509 certificate fingerprints, and allows verified
protocol proofs to use the existing byte-array size limit instead of the
smaller general-container limit.

No public C++ signature, API descriptor, wire record, persisted format, package
component, or Contract SDK ABI changes in this release.

## Linux Portability

Module implementation units now include the standard declarations they use
directly. This removes transitive-header dependence for condition variables,
integer and vector types when building with LLVM and libstdc++ on Linux.

Raw optional decoding now value-initializes a described aggregate explicitly.
Canonical Raw bytes and malformed-input behavior are unchanged.

## X.509 Fingerprints

`forge::crypto::pki::x509::certificate::fingerprint_sha256()` now returns the
standard SHA-256 digest of the certificate's DER bytes. The previous
implementation accidentally hashed Forge's length-prefixed Raw representation
of the byte vector.

Deployments that copied a certificate pin produced by Forge 8.29.0 development
code must recompute it as SHA-256 over DER. Pins obtained from standard OpenSSL,
browser, PKI or certificate-management tooling already use the corrected
definition. TLS verification remains mandatory; no fallback or verification
disablement was added.

## Protocol Byte Arrays

Variant conversion for `std::vector<std::uint8_t>` now uses
`MAX_SIZE_OF_BYTE_ARRAYS`, matching the existing byte-array policy. Other
vectors remain bounded by `MAX_NUM_ARRAY_ELEMENTS`.

This fixes verified Chain API responses whose valid Savanna finality witness is
larger than one MiB. The HTTP/API DTO, JSON shape, witness bytes and proof
verification rules do not change; the client and server simply accept valid
byte arrays up to the already configured byte-array bound.

## Repository Identity

Canonical repository references now point to `https://github.com/crossfed/forge`.
This is metadata only and does not affect package or runtime behavior.

## Validation Scope

The implementation commits were validated locally with focused Raw, Variant,
PKI, TLS and Chain API tests. The aggregate Forge test target passed on ARM64,
and the exact Forge commit was then consumed by a clean Linux container build
and the full 38-test ARM64 Spine CTest suite. Spine's live container acceptance
also verified an authenticated Chain API response with a finality proof larger
than one MiB and standard DER certificate pinning.

GitHub CI was not manually dispatched for this release preparation.
