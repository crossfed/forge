# Forge 8.22.0

Forge 8.22.0 begins the P2P production-hardening implementation with bounded
peer state, asynchronous persistence, node-owned Kademlia routing and
secret-backed official-plugin startup. It also adds the reusable one-shot CLI,
local transaction, encrypted keystore and chain-history foundations needed by
product command-line clients.

The libp2p protocol IDs and wire messages do not change. The low-level C++
peer-store contract, its private persisted cache, and the official P2P plugin
configuration have an explicitly approved pre-stabilization clean break.

## CLI And Local Transactions

The new `cli` package component provides typed nested commands, options,
validation, contextual help, shell completion, machine-readable descriptors and
an asynchronous one-shot runner. CLI11 2.6.2 is a private implementation
dependency: its headers, symbols and exceptions are not part of Forge's public
surface. `forge.config.program_options` remains the daemon/configuration parser.

The new `chain_transaction` component owns local TAPOS, expiration, action
assembly, signing and packing over canonical `forge.chain.protocol` values. It
does not open network connections or duplicate `forge.chain.api`. The companion
`crypto_signer` provider interface and `crypto_keystore` encrypted-file provider
support offline signing without coupling command-line clients to the node signer
plugin. Passwords are read from a hidden terminal, standard input or a bounded
owner-only file; secrets are never accepted as command-line arguments.
Keystore encryption always generates its salt and AES-GCM nonce internally.
Long-lived entries use securely erased encoded secret storage, and an atomic
write that was published but could not be directory-synced reports the typed
`durability_unknown` state without leaving the live signer on stale keys.

Encrypted secret files written by the pre-8.22 Crypto Secrets helper used the
`FCLSEC1` container and are intentionally not read by the new `FORGEKS` format.
Before upgrading, decrypt those files with the previous Forge release and
re-encrypt the plaintext with `forge.crypto.keystore.encrypted_file`, then
atomically replace the configured file with mode `0600`. Forge does not ship a
legacy reader or an in-place migration path for this pre-stable persisted
format.

The source migration is mechanical:

| Removed Crypto Secrets helper | Forge 8.22 replacement |
|---|---|
| `encrypt_secret_file(encrypted_file_encrypt_request)` | `forge::crypto::keystore::encrypt_file(encrypted_file_request)` |
| `decrypt_secret_file(container, std::string, encrypted_file_decrypt_limits)` | `forge::crypto::keystore::decrypt_file(container, password, limits)` |
| plaintext `core::bytes` / passphrase `std::string` | `forge::crypto::core::secret_bytes` / `secret_string` |
| request KDF fields / `encrypted_file_decrypt_limits` | `encryption_options` / `decrypt_limits` |

The Crypto Secrets plugin now delegates persistence encryption to the same
keystore codec instead of maintaining a second container implementation.

## Chain History

`forge.chain.api.history` adds typed transaction lookup, transaction and block
traces, and paginated account actions. Its wire DTOs live in
`forge.chain.protocol.history_query`; the existing raw and verified clients gain
history operations without introducing another client facade. Transaction
lookup is verified through inclusion and finality. Product-specific trace and
account-history projections remain fail-closed until the product supplies its
projection verifier.

## Peer Store Migration

`forge::net::p2p::peer_store::backend`, `backend_kind`, `rocksdb_options`,
`make_memory_backend()` and `make_rocksdb_backend()` are removed. A direct node
owner now supplies an asynchronous `peer_store::persistence` implementation in
`peer_store::options::persistence`. The port owns paged hydration, atomic
mutation batches, bounded expiry pruning, flush and close. The deterministic
memory implementation is available through `make_memory_persistence()` for
tests only.

Provider and Rendezvous mutations are now awaited. Replace `upsert_provider`,
`upsert_rendezvous` and `remove_rendezvous` with their `async_*` forms and
`co_await` the result. Peer observations remain synchronous bounded operational
updates and are durably coalesced by `async_flush()` or `async_close()`.
Rendezvous server admission enforces its per-peer registration limit before
durable persistence, while discovered TTL values are converted into local
absolute expiry timestamps before caching.

The removed RocksDB cache format is not read by the new ObjectDB adapter. Delete
the old P2P peer-cache database or key prefix before upgrade. It contains
re-discoverable peer history rather than application authority; the new cache
is hydrated again from configured bootstrap peers. Forge does not provide a
legacy decoder or an automatic startup scan.

## Official Plugin Configuration

Inline `certificate-pem` and `private-key-pem` fields are removed from
`plugins.p2p.node`. Configure a dedicated DB Store Object layer and Crypto
Secrets references instead:

```yaml
plugins:
   p2p:
      node:
         peer-store:
            store: p2p-peer-state
         identity:
            certificate-secret: p2p/node-certificate
            private-key-secret: p2p/node-private-key
```

The plugin declares dependencies on `plugins.db.store` and
`plugins.crypto.secrets`, registers its private ObjectDB schema during
`after_initialize()`, and loads identity plus bounded peer state before opening
listeners. Production startup fails closed for a missing named store, missing
secret, incompatible schema, or persistence failure. `allow-insecure-test-mode`
continues to permit explicit memory-only test fixtures, but is not a production
configuration.

The plugin version is `2.0.0`. Its local API contract remains `1.0`; application
method signatures and libp2p wire compatibility are unchanged.

Low-level P2P, QUIC and STCP option structs keep their existing `std::string`
private-key fields for source compatibility. They do not promise secure erasure
of caller-owned copies. The production P2P plugin obtains identity material from
Crypto Secrets, clears its temporary and retained plaintext buffers after node
construction, and clears them again on failed startup and shutdown.

## Kademlia Scope

The node now owns bounded XOR-distance k-buckets with replacement lists,
verified-server admission and failure eviction. Durable history supplies
untrusted startup candidates only. Standard Kademlia value operations,
autonomous refresh, provider republishing and full topology ownership remain
later hardening stages and are not claimed as production support in this
release.
