# Forge 8.12.0

Forge 8.12.0 splits the former `forge_crypto` monolith into focused leaf
libraries. This is an explicitly approved pre-stabilization source and package
break. Cryptographic results, Raw and Variant bytes, algorithm values, keys,
signatures and persisted layouts are unchanged.

## Package Migration

The `forge_crypto` target and `crypto` package component have no aggregate
replacement. Consumers must request and link every leaf they use.

| Previous target/component | Replacement target/component | Responsibility |
| --- | --- | --- |
| `forge_crypto` / `crypto` | `forge_crypto_core` / `crypto_core` | Bytes, secret storage and random data |
| `forge_crypto` / `crypto` | `forge_crypto_digest` / `crypto_digest` | Digests, HMAC and Raw pack hashing |
| `forge_crypto` / `crypto` | `forge_crypto_symmetric` / `crypto_symmetric` | AES, ChaCha20-Poly1305 and KDFs |
| `forge_crypto` / `crypto` | `forge_crypto_asymmetric_values` / `crypto_asymmetric_values` | Binary key/signature values without host algorithms |
| `forge_crypto` / `crypto` | `forge_crypto_asymmetric` / `crypto_asymmetric` | Host signing, verification and text encoding |
| `forge_crypto` / `crypto` | `forge_crypto_pki` / `crypto_pki` | DER, PEM and X.509 |
| `forge_crypto` / `crypto` | `forge_crypto_math` / `crypto_math` | Big integers and modular arithmetic |
| `forge_crypto` / `crypto` | `forge_crypto_bls` / `crypto_bls` | BLS values and operations |
| `forge_crypto` / `crypto` | `forge_crypto_bn256` / `crypto_bn256` | BN254 operations |
| `forge_crypto` / `crypto` | `forge_codec_base32` / `codec_base32` | Base32 text encoding |

For example:

```cmake
find_package(Forge CONFIG REQUIRED
   COMPONENTS crypto_digest crypto_asymmetric_values)

target_link_libraries(app PRIVATE
   Forge::forge_crypto_digest
   Forge::forge_crypto_asymmetric_values
)
```

## Module Migration

| Removed module or group | Replacement |
| --- | --- |
| `forge.crypto.types` | `forge.crypto.core.types` |
| `forge.crypto.secret_bytes` | `forge.crypto.core.secret_bytes` |
| `forge.crypto.random` | `forge.crypto.core.random` |
| `forge.crypto.{sha1,sha224,sha256,sha3,sha512,ripemd160,blake2,hmac,packhash}` | `forge.crypto.digest.{sha1,sha224,sha256,sha3,sha512,ripemd160,blake2,hmac,packhash}` |
| `forge.crypto.{sha256,sha512,ripemd160}:value` | `forge.crypto.digest.{sha256,sha512,ripemd160}:value` |
| `forge.crypto.{aes,chacha20_poly1305,kdf}` | `forge.crypto.symmetric.{aes,chacha20_poly1305,kdf}` |
| `forge.crypto.asymmetric.value` | `forge.crypto.asymmetric.values` |
| `forge.crypto.{secp256k1,p256,ed25519,rsa,x25519,webauthn}` | `forge.crypto.asymmetric.{secp256k1,p256,ed25519,rsa,x25519,webauthn}` |
| `forge.crypto.{der,pem,x509}` | `forge.crypto.pki.{der,pem,x509}` |
| `forge.crypto.{bigint,modular_arithmetic}` | `forge.crypto.math.{bigint,modular_arithmetic}` |
| `forge.crypto.base32` | `forge.codec.base32` |

`forge.crypto.digest`, `forge.crypto.asymmetric`, `forge.crypto.bls`,
`forge.crypto.bls.{values,primitives}` and `forge.crypto.bn256` keep their
module names, but consumers must link their new owning leaf targets. Public
symbols now belong to `forge::crypto::core`, `digest`, `symmetric`,
`asymmetric`, `pki`, `math`, `bls` or `bn256`; `forge::crypto` is only a
grouping namespace.

## CityHash Removal

The public module `forge.crypto.city` and the root functions
`forge::crypto::city_hash32`, `city_hash64`, `city_hash128` and CRC variants
were removed. Forge had no first-party consumer or persisted contract for this
non-cryptographic hash, and there is no drop-in Forge replacement.

Downstream code with an existing CityHash wire or persisted contract must keep
a CityHash implementation at that compatibility boundary. Choosing a digest
from `forge_crypto_digest` changes the algorithm and stored bytes, so it must be
introduced as a new format rather than used as a silent substitution.
