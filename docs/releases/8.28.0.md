# Forge 8.28.0

Forge 8.28.0 adds typed server-supplied request fields and explicit ownership
for API-over-P2P publications.

## Server-Supplied Fields

`forge.api.core.server_supplied` lets an API declare request fields that are
owned by the server transport boundary. Clients clear these fields before
serialization. After decoding a unary request or stream-open payload, the
server fills them from trusted invocation metadata. Required values fail
closed when the transport cannot supply them.

This removes the need for application interceptors that decode and repack an
entire payload merely to replace authenticated caller context. The mechanism
is product-neutral: Forge defines traversal and validation, while a field's
specialization defines how trusted invocation metadata maps to its value.

## Owned P2P Publications

The P2P node and resolver APIs now return a move-only
`forge::api::p2p::publication`. Destroying or explicitly closing the handle
removes the route, rejects new calls and cancels calls owned by that
publication. Replacement uses a generation token, so a stale handle cannot
remove a newer publication of the same protocol.

The local node and resolver API contracts move from major 1 to major 2.
Callers must retain the returned publication handle for as long as the API is
intended to remain available. Discarding the return value now immediately
unpublishes the API.

## Validation

Focused local ARM64 validation covers spoofed and missing server-supplied
values for unary and stream-open calls, route replacement, publication
shutdown and in-flight cancellation. API Core, P2P plugin, managed remote and
relocated package consumers pass with Clang 22. GitHub CI and Codex review were
intentionally not run for this release.
