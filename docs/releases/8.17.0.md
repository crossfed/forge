# Forge 8.17.0

Forge 8.17.0 exposes the effective durability mode of configured MDBX stores
through the typed DB Store status API. This is an explicitly approved
pre-stable source and API-contract break. Chain wire encodings and persisted
database layouts remain compatible with Forge 8.16.1.

## DB Store Durability Status

`forge::plugins::db::store::store_status` now contains:

```cpp
std::optional<std::string> durability;
```

Configured MDBX stores report their effective mode after defaults are applied:
`durable-sync` or `safe-nosync`. RocksDB stores and programmatic custom drivers
report no value because DB Store does not own enough information to infer an
external driver's acknowledgement contract.

This allows products that persist safety-critical state to reject
`safe-nosync` through the generic DB Store API without importing MDBX or
duplicating physical backend configuration.

The `forge.plugins.db.store` API contract changes from `1.2` to `2.0`. The
major version changes because `store_status` is returned by value and its
binary layout changed. No compatibility alias or legacy status shape is
provided.

## Migration

Consumers that aggregate-initialize `store_status` must insert the new
`durability` field between `driver` and `path`, or switch to designated
initializers:

```cpp
auto status = forge::plugins::db::store::store_status{
   .name = "state",
   .driver = "mdbx",
   .durability = "durable-sync",
   .path = "state",
};
```

API clients must update the expected contract to `2.0` and regenerate any
derived bindings. Consumers requiring durable acknowledgement should require a
present value equal to
`durable-sync`; an absent value is not evidence of durability.

All C++ consumers must rebuild. Database reset, replay and migration are not
required because no persisted record or physical key layout changed.
