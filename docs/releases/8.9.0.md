# Forge 8.9.0

Forge 8.9.0 changes the local Crypto Signer contract to return typed binary
Forge Crypto values. This is an explicitly approved pre-stabilization
source/config break. Existing `asymmetric::public_key` and
`asymmetric::signature` binary layouts are unchanged.

## Source Migration

The API contract version is now `2.0` and the plugin version is `2.0.0`.

| Forge 8.8 | Forge 8.9 |
| --- | --- |
| `key_algorithm` | `forge::crypto::asymmetric::algorithm` |
| `required_algorithm = key_algorithm::any` | `required_algorithm = std::nullopt` |
| `request::output_profile` | removed |
| `options::output_profile` | removed |
| `response::algorithm` | `response.signature.type()` |
| text `response::public_key` | typed `asymmetric::public_key` |
| byte-vector `response::signature` | typed `asymmetric::signature` |
| `response::signature_text()` | explicit consumer-side encoding |
| config `default-output-profile` | removed and rejected |

The signing call is now:

```cpp
auto result = co_await signer->sign({
   .key_id = "service-key",
   .purpose = "api.receipt",
   .digest = digest,
   .required_algorithm =
      forge::crypto::asymmetric::algorithm::secp256k1,
});
```

Binary consumers serialize the typed values directly:

```cpp
auto bytes = forge::raw::pack(result.signature);
```

Text consumers choose an encoding explicitly at their boundary:

```cpp
auto text = forge::crypto::asymmetric::encoding::antelope().format(
   result.signature);
```

`key::input_profile` and programmatic `plugin_options::profiles` remain
available only for parsing configured private-key text.

## Compatibility

The signer remains local-only, so no remote wire contract is migrated.
Contract id, target, component and module names are unchanged. This release
does not alter persisted database, chain protocol or existing Forge Crypto Raw
formats. Compatibility aliases and legacy response fields are intentionally
not provided.
