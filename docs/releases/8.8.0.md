# Forge 8.8.0

Forge 8.8.0 moves compact database object identifiers into the DB family. This
is an explicitly approved pre-stabilization source/package break. Runtime
behavior, raw bytes, Variant shapes and persisted database layouts are
unchanged.

## Source Migration

| Forge 8.7 | Forge 8.8 |
| --- | --- |
| target `forge_ids` | target `forge_db_ids` |
| component `ids` | component `db_ids` |
| `Forge::forge_ids` | `Forge::forge_db_ids` |
| `import forge.ids.object_id;` | `import forge.db.ids.object_id;` |
| namespace `forge::ids` | namespace `forge::db::ids` |
| `libraries/ids` | `libraries/db/ids` |

The migration is mechanical:

```cpp
import forge.db.ids.object_id;

using account_id = forge::db::ids::typed_id<1, 2>;
auto id = account_id{42};
```

Package consumers now request and link the DB-family component:

```cmake
find_package(Forge CONFIG REQUIRED COMPONENTS db_ids)
target_link_libraries(my_target PRIVATE Forge::forge_db_ids)
```

No compatibility aliases, forwarding modules or deprecated targets are
provided.

## Compatibility

`object_id` still serializes as `space`, `type`, then `instance`, using the
same 11 bytes. `typed_id` remains instance-only in Raw and Variant forms.
Object record keys, ranked indexes, Revision metadata and Blob owner identities
therefore retain their existing persisted representation.

The exception approved for this release is source/package-only and applies
only to the DB IDs ownership move. It does not relax Forge wire or persisted
storage compatibility rules.
