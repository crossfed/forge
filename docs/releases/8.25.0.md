# Forge 8.25.0

Forge 8.25.0 hardens Raw stream ownership, application service lookup and
encrypted-keystore input validation. Chain protocol, BLS wire bytes and
persisted formats do not change.

## Raw Stream Ownership

`forge::raw::detail::make_input_stream` is no longer exported because its
non-owning input span could outlive a temporary container. Consumers migrate to
`raw::unpack(...)` or `raw::unpack_exact(...)`; there is no compatibility alias.

The vector `datastream::storage() const` overload is also removed. Lazy
materialization is now an explicit mutation on a non-const stream, so const
access no longer hides a write to internal storage.

## Application Services

Application services add `service_view::try_get<T>()` and
`connect_context::try_service<T>()` for optional lookup. Registry publication,
lookup, close and clear are synchronized. A detached view now reports typed
`service_registry_detached` rather than `service_missing`; `close()` and
`clear()` are no longer declared `noexcept` because acquiring the registry lock
can report a system failure.

## Keystore Input Hardening

CLI passphrases have one supported input boundary:
`forge.crypto.keystore.password`. Interactive input disables terminal echo;
non-interactive callers use standard input or an owner-only regular password
file. Secret values are not argv options or ordinary config fields.

Keystore decrypt rejects non-power-of-two scrypt `N`, non-canonical salt and
nonce sizes, and inconsistent container lengths before scrypt or AES. Existing
valid keystore bytes are unchanged.

## Compatibility

The Raw and detached-service changes are approved pre-stable source breaks.
Migration is mechanical: replace direct use of the former Raw detail helper
with `raw::unpack(...)` or `raw::unpack_exact(...)`, call `storage()` on a
mutable stream, and catch `service_registry_detached` when distinguishing an
invalid view from a missing required service. Compatibility aliases are not
provided.
