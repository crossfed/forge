# Forge 8.19.0

Forge 8.19.0 completes the shared host/guest serialization surface for
producer and finalizer policy records and adds exact typed JSON decoding.
Chain raw encodings and persisted database layouts remain compatible with
Forge 8.18.0.

## Chain Protocol Serialization

The following Spring-compatible records now have one guest-safe value
definition and a complete host Raw/Variant serialization surface:

- producer authority and producer authority schedule;
- finalizer authority and finalizer policy;
- block signing authority.

Equality is defined by the canonical records instead of downstream manual
visitors. Contract SDK guest projects receive the same value partitions as
host consumers.

`block_signing_authority` uses the canonical Spring/FC Variant form:

```json
[0, {"threshold": 1, "keys": []}]
```

Its Raw encoding is unchanged.

## Exact Typed JSON

`forge.codec.json` now exposes:

```cpp
forge::codec::json::read_options options;
options.described_records =
   forge::codec::json::described_record_policy::exact;

auto result = forge::codec::json::load<configuration>(path, options);
```

Exact decoding recursively validates described records, arrays, associative
containers, optionals, pointers and `[index, payload]` variants. Unknown or
missing members, duplicate keys, invalid variant indices, non-canonical scalar
spellings and lossy numeric conversions produce diagnostics with their exact
path.

Schema-aware Variant mapping is shared by JSON and YAML. Nested schema records
therefore retain canonical field names and validation paths across both
codecs.

## Migration

The former object-only JSON spelling for `block_signing_authority` is not
accepted. Regenerate configuration with the canonical Variant representation:

```json
[0, {"threshold": 1, "keys": [{"key": "...", "weight": 1}]}]
```

Downstream manual parsing and comparison code should be replaced with typed
`forge::codec::json::load<T>` and the canonical equality operators.

All C++ and Contract SDK consumers must rebuild. Contract state reset,
blockchain replay and database migration are not required.

## Validation

The exact reviewed feature head was validated by Contract SDK run
`30594415421` on macOS 15 ARM64 and Ubuntu 24.04 x86_64. Both lanes built and
relocated the developer SDK, compiled generated contracts, executed them in
Forge VM and passed the unchanged Spring/EOSIO compatibility corpus.
