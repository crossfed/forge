# Forge 8.11.0

Forge 8.11.0 gives producer schedule protocol records a single canonical module
owner. It is a compatible feature release over Forge 8.10.0.

## Chain Protocol

The new public leaf module:

```cpp
import forge.chain.protocol.producer_schedule;
```

owns:

- `forge::chain::protocol::producer_key`;
- `forge::chain::protocol::producer_schedule`;
- their comparison and Raw serialization contracts.

`forge.chain.protocol.block` and
`forge.chain.protocol.producer_authority` re-export the canonical module. Code
that imports either existing surface therefore continues to compile, while a
translation unit may now import both without conflicting module definitions.

The Contract SDK foundation, BMI maps, ABI tooling and installed package assets
also include the new leaf module.

## Compatibility

Public names, namespace, fields, defaults, comparison behavior, variant
representation and Raw field order are unchanged. Spring-compatible fixed Raw
fixtures cover both producer records.

No source, wire or persisted-data migration is required. Consumers may keep an
existing `block` or `producer_authority` import, or import
`producer_schedule` directly when that is the only protocol surface needed.

## Validation

The release change is covered by:

- joint imports of `block`, `producer_authority` and `producer_schedule`;
- type-identity checks for `block_header::new_producers`;
- fixed Raw golden fixtures and host variant round trips;
- installed `chain_protocol` package consumption;
- wasm32 Contract SDK foundation, ABI fixture and reproducibility builds.
