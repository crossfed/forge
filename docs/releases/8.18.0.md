# Forge 8.18.0

Forge 8.18.0 exports the deterministic Contract SDK execution host as an
installed package component and documents the canonical workflow for
dual-target protocol libraries. This is an additive minor release. Chain wire
encodings and persisted database layouts remain compatible with Forge 8.17.0.

## Contract Testing Component

Downstream contract projects can now request and link the public test host:

```cmake
find_package(Forge CONFIG REQUIRED COMPONENTS contract_testing)

target_link_libraries(
   contract_state_tests
   PRIVATE Forge::forge_contract_testing
)
```

The component exposes `forge::contract::testing::host`, its deterministic
oracle state and typed exceptions. A host invocation executes against one
Forge ObjectDB transaction: success commits, while assertions, database
errors, VM traps and execution timeouts roll back the invocation.

Contract execution is bounded by `execution_limits.timeout`, which defaults to
five seconds. Direct and synchronous nested guest calls share one absolute
deadline. Consumers that intentionally exercise long-running contracts must
choose an explicit positive timeout rather than relying on unbounded
execution.

The installed component is covered by single-configuration and
multi-configuration relocation consumers, including custom CMake
configuration names. Package metadata remains relocatable and does not install
build-tree module artifacts.

## Contract Library Workflow

`skills/create-contract-library/SKILL.md` defines the downstream workflow for
libraries declared with `forge_add_contract_library`. Such libraries apply the
normal Forge library layout first, then declare their complete host and WASM
source/dependency graph through the Contract SDK API.

Shared action payloads own their canonical action name through `get_name()`.
Host code packs the payload with `forge::raw`, guest dispatch unpacks the same
type, and ABI fields are emitted directly without a wrapper object. Persisted
types and pure checked calculations can therefore be tested on the host and in
the generated WASM contract from one definition.

## Migration

Existing internal users of the former contract test host should replace
private test-target dependencies with the installed component:

```cmake
find_package(Forge CONFIG REQUIRED COMPONENTS contract_testing)
target_link_libraries(my_tests PRIVATE Forge::forge_contract_testing)
```

Downstream package tests should configure a fresh consumer from the installed
prefix. Multi-configuration callers must propagate both the active
configuration and the complete `CMAKE_CONFIGURATION_TYPES` list so custom
configurations remain available after relocation.

All C++ consumers must rebuild. Contract state reset, blockchain replay and
database migration are not required.
