# Forge 8.2.0

Forge 8.2.0 adds DB Core savepoints and transaction participants, durable DB
Revision storage, and optional Revision integration in the DB Store plugin.

This release also introduces explicit contract stability rules. Public
contracts are Stable by default. A library may allow documented source-level
changes in a MINOR release only when its owning README marks the affected API as
Preview or Experimental.

## Stability

The following source surfaces are Preview in Forge 8.x:

- DB Core savepoint, participant and record-lock extensions;
- DB Object public C++ API;
- DB Revision public C++ API;
- DB Store plugin C++ API and local API contract.

Source stability does not implicitly change wire or persisted storage
stability. Existing application object/index and blob record layouts are not
redefined by this release. Revision journal rows and blob retention barriers are
new records created only when Revision is explicitly enabled and joined.

## Source Migration From 8.1

DB Object typed-ID lookup now belongs to the DB Object domain:

```cpp
// Forge 8.1
using index = forge::db::object::object_index_for_id_t<account::id_t>;

// Forge 8.2
using index = forge::db::object::index_for_id_t<account::id_t>;
```

`FORGE_DB_OBJECT(account_index)` keeps the same invocation. Code that manually
provided the inverse mapping must specialize
`forge::db::object::index_for_id<Id>` instead of
`forge::ids::type_for_id<Id>`.

Joining an Object store now waits for its writer lane and is asynchronous:

```cpp
// Forge 8.1
auto objects = store.join(tx);

// Forge 8.2
auto objects = co_await store.join(tx);
```

The same change applies to `plugins.db.store` Object handles. DB Object
transactions are move-only; pass them by reference when joining an existing
Object transaction and move them when transferring ownership.

## New DB Facilities

- DB Core transactions expose native savepoint create, rollback and release
  operations where supported by the backend.
- Transaction participants keep Object, Blob and Revision state synchronized
  with savepoint and outer transaction boundaries.
- `forge_db_revision` records before-images atomically with application changes,
  supports strict-head revert and bounded whole-revision pruning.
- `plugins.db.store` can enable Revision with `revision: {}` and explicitly join
  it to the same named-store transaction used by Object and Blob layers.
