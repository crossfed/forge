# Forge 8.14.0

Forge 8.14.0 hardens the Preview `forge_chain_savanna` kernel for bounded
long-running validation, quorum-certificate construction and durable
finalizer-safety integration.

Execution, controller state, persistence implementations, networking, key
custody and plugins remain downstream responsibilities. The release does not
change Stable APIs, protocol records, QC bytes, finality digest preimages or
other persisted Forge layouts.

## Bounded Validation

`validation_state` is now an encapsulated, versioned value. It retains:

- a compact Merkle frontier for finalized history;
- the current frontier;
- the first retained block;
- roots and leaf preimages for the caller-selected reversible window.

`append()` updates the state in `O(log N)` time. `advance_finalized()` retains
the finalized root while discarding older roots and preimages. `root_at()`
reports `validation_root_unavailable` for pruned history, and Raw decoding
rejects unsupported versions or inconsistent frontiers with `codec_error`.

## Vote Accumulation

The new `forge.chain.savanna.vote` and
`forge.chain.savanna.vote_accumulator` modules provide:

- canonical strong and weak vote messages;
- thread-safe active/pending policy vote collection;
- duplicate, conflict, block, finalizer and signature diagnostics;
- complete local and observed QC selection without mixing policy halves;
- verified QC capabilities bound to the checked finality digest.

The accumulator is move-only and ephemeral. Products own network queues,
unknown-block buffering and persistence policy.

## Finalizer Safety

The new `forge.chain.savanna.finalizer_safety` module implements neutral
cross-candidate monotonicity, higher-QC liveness and ancestry-lock safety.
`vote_plan.next` must be durably stored by the downstream controller before it
signs or publishes a vote.

Forge serializes the versioned safety value but does not own its DB or file
storage. Private keys and proof-of-possession material are not serialized.

## Preview Migration

The Forge 8.13.0 Preview Raw layout for `validation_state` is intentionally not
decoded by 8.14.0. Consumers that persisted that experimental value must
reconstruct it from trusted validation leaves using `make_validation()` and
`append()`, then apply their finalized boundary with `advance_finalized()`.

There is no compatibility alias, forwarding decoder or automatic replay.
Existing QC, policy-diff, finality-digest and validation-root compatibility
fixtures remain byte-for-byte unchanged.
