# Forge 8.16.0

Forge 8.16.0 adds dual-target Contract SDK libraries and fixes digest lifetime
and P2P lifecycle defects found while integrating a multi-node validator. It
contains explicitly approved pre-stable clean breaks in the digest source API
and Contract SDK manifest schema. Chain wire encodings and persisted database
layouts remain compatible with Forge 8.15.0.

## Dual-Target Contract Libraries

`forge_add_contract_library()` declares one immutable, typed source and
dependency graph for host compilation, wasm32 guest compilation, ABI
generation, relocatable source packaging and source attestation. Public and
private dependency edges are explicit; Forge no longer reconstructs a second
toolchain graph by reading native CMake link properties.

A shared action DTO may expose a canonical `get_name()` function. Host code
packs that DTO directly with Forge Raw, the guest dispatcher unpacks the same
type, and the generated ABI exposes the DTO fields directly rather than through
a wrapper object. Legacy handlers without `get_name()` retain their existing
wrapper ABI.

Installed contract-library packages contain prefix-relative sources, modules
and headers plus exported graph metadata. They do not install compiler-specific
BMI or PCM module artifacts. Contract manifests use schema v2 with a
deterministic source graph and graph digest.

The new `forge_add_contract_library()` declaration/materialization API and the
host request APIs identified in their owning READMEs are Experimental. The
contract graph descriptor and reader, canonical annotation payloads, generated
ABI/dispatcher behavior, manifest schema v2 field meanings, validation policy
and stable library identities remain versioned compatibility contracts.

Manifest v1 is not emitted as a compatibility mode; contract artifacts and
installed protocol packages must be rebuilt with Forge 8.16.0. Consumers of
the generated sidecar must accept schema v2 and its required `source_graph`.

## Digest Borrowing

Fixed-size digest values no longer allow borrowed byte views to be created
from temporary objects. The `data()` and `to_uint8_span()` accessors remain
available on lvalues and are deleted for rvalues.

This turns a dangling-view runtime defect into a compile-time diagnostic
without changing digest bytes, comparison, hashing or serialization.
Out-of-line `sha1`, `sha224` and `sha3` accessors also gain matching
ref-qualified signatures, so downstream binaries must be rebuilt.

Code that borrowed from a temporary must bind the digest first:

```cpp
auto digest = forge::crypto::digest::sha256::hash(input);
auto bytes = digest.to_uint8_span();
```

## P2P Bootstrap Lifecycle

Configured bootstrap connections are now maintained for the full P2P plugin
lifetime. A disconnected bootstrap peer is retried with bounded exponential
backoff, and a peer that starts after the local node can connect without
restarting either process.

Bootstrap maintenance publication and cancellation are race-safe. Timer
arming and posted cancellation are serialized on an Asio strand, so shutdown
cannot lose a stop request on a multi-worker runtime.

P2P shutdown cancels active TCP and QUIC dials before waiting for bootstrap
maintenance, waits for the node and Yamux read loops to finish, and rejects
sessions whose handshake completes after shutdown begins. A maintenance-task
error does not skip transport shutdown, and repeated node lifecycle tests no
longer retain unfinished transport work.

`request_stop()` synchronously closes P2P admission and listeners and initiates
session disconnect before the application enters asynchronous shutdown.
`shutdown()` retains and awaits the already-started transport teardown instead
of treating an empty logical session set as completed STCP/Yamux cleanup.

The shared QUIC listener socket serializes receive, send and stop initiation.
Each connection returns to its own strand after a shared-socket send before
touching connection-owned queues or lifecycle state.

## Migration And Compatibility

Forge 8.15.0 source that calls `data()` or `to_uint8_span()` on a temporary must
adopt the named-lvalue pattern above. All consumers must rebuild because the
ref-qualified out-of-line digest symbols changed. No compatibility aliases are
provided for the unsafe rvalue borrowing contract.

Contract-library consumers should move shared host/guest inputs into an
explicit `forge_add_contract_library()` descriptor and declare public and
private dependencies there. Native CMake target mutation is not a supported
cross-toolchain contract graph.

No chain protocol record, chain wire encoding or persisted database layout
changed. Database migration is not required. Contract manifests are generated
artifacts and must be regenerated; Forge intentionally provides no schema-v1
compatibility mode.
