# Forge 8.27.0

Forge 8.27.0 adds product-neutral managed P2P remotes and a narrowly scoped
configured signing provider for application composition.

## Managed P2P Remotes

`forge.plugins.p2p.resolver.managed` 1.0 creates a stable remote API handle
from an ordered set of peers. It performs the initial connection, preserves a
sticky peer while healthy, coalesces reconnect attempts and applies bounded
backoff, waiter and capacity limits. Cancellation and shutdown are propagated
through typed errors.

An API invocation that fails after dispatch is never replayed automatically.
The failed call is returned to its caller, the broken generation is
invalidated and only a subsequent request may reconnect. Transaction clients
must recover uncertain submissions by transaction identifier and verified
finality rather than blind resubmission.

## Configured Signing Provider

`forge.crypto.signer.configured_provider` exposes exactly one configured key
through the existing signer provider interface. Applications choose either an
inline secret supplied by Forge Config or a bounded private-key file; the
provider never reads process environment variables itself.

On POSIX systems private-key files must be regular, owned by the effective
user, opened without following symbolic links and have mode `0400`. Invalid,
duplicate or unavailable key sources fail with typed signer errors. Temporary
private-key material is explicitly cleared across supported asymmetric
encoding and move paths.

## Validation

Focused local ARM64 validation covers managed reconnect, failover, no-replay,
cancellation and concurrency behavior; inline and file-backed signing,
asymmetric key handling, structure checks and relocated package consumers.
GitHub CI and Codex review were intentionally not run for this release.
