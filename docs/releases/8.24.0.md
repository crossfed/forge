# Forge 8.24.0

Forge 8.24.0 makes BLS protocol values available to host and contract builds
through one fixed representation and gives Savanna finalizer records one
canonical owner. It is an intentionally approved pre-stable source and JSON
break over Forge 8.23.0. Existing valid raw wire bytes do not change.

## BLS Values

`forge.crypto.bls.values` now owns fixed `public_key`, `signature`, and
`aggregate_signature` records. They contain 96 or 192 bytes, comparison,
fixed-byte access, and raw serialization. The value component is freestanding
and does not expose BLS12-381 backend objects.

Host cryptographic operations remain in `forge.crypto.bls`. Public-key and
signature validation return `false` for malformed untrusted points. Proof of
possession produces a capability that retains the decoded operational key, and
Savanna vote verification can reuse it without decoding that key again.
`signature_accumulator` validates each input and rejects empty or invalid
aggregates with typed BLS exceptions.

Text and Variant serialization use canonical `PUB_BLS_` and `SIG_BLS_` forms.
The former hexadecimal JSON representation is intentionally rejected.

## Savanna Values

The new `forge_chain_savanna_values` component and
`forge.chain.savanna.values` module own `finalizer` and `finalizer_policy`.
`forge::chain::protocol::finalizer_authority` remains an import-compatible alias
to the canonical finalizer record, while the duplicated vector-backed protocol
definition is removed.

The EOSIO contract veneer retains its donor-compatible `vector<char>` source
record and performs the checked conversion at the contract ABI boundary.
Contract-facing Forge protocol and Savanna APIs use the fixed BLS value.

## Migration

The source migration is mechanical:

- replace BLS string constructors with `encoding::parse_public_key`,
  `encoding::parse_signature`, or `encoding::parse_aggregate_signature`;
- replace `to_string()` with `encoding::format(...)`;
- replace mutable `aggregate_signature::aggregate(...)` with
  `signature_accumulator::add(...)` and `finish()`;
- replace `public_key_value` and `signature_value` with `public_key` and
  `signature`;
- use `public_key::serialize()` or `bytes()` for a fixed byte projection;
- migrate protocol finalizer fields from `vector<char>` to
  `forge::crypto::bls::public_key`;
- emit canonical BLS text in JSON rather than hexadecimal byte strings.

Compatibility aliases and legacy JSON readers are not provided. Raw encoding
remains `varuint(size) + bytes`, so valid public keys, signatures, finalizer
policies, and downstream chain identifiers retain their previous bytes.

## Validation

Local ARM64 validation covers fixed value ordering and raw goldens, malformed
points and sizes, proof of possession, aggregation, grouped verification,
Savanna policy and quorum-certificate flows, signer BLS APIs, host and guest
type identity, installed package consumers, unchanged EOSIO source consumers,
Contract SDK foundation and relocation, structure, formatting, and diff gates.
