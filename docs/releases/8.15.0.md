# Forge 8.15.0

Forge 8.15.0 extends the existing Crypto Signer plugin with a local-only,
purpose-scoped BLS API for downstream finality services.

The release does not change the asymmetric signer API v2, Savanna wire types,
quorum-certificate bytes or persisted database layouts.

## BLS Signer API

The `forge.plugins.crypto.signer.bls` contract provides:

- `describe(key_id, purpose)`, returning the configured public key and proof of
  possession;
- `sign(key_id, purpose, message)`, returning the public key and BLS signature
  over the exact supplied bytes.

BLS keys are configured through the secret `bls-keys` list. Every key has a
stable id and an allow-list of purposes. Both methods enforce that allow-list;
private-key material never appears in API responses, schema output or logs.

Products remain responsible for canonical message construction, domain
separation, policy membership and durable finalizer-safety state. The signer
does not implement consensus or assign meaning to a purpose string.

## Proof Of Possession

`describe` exposes the proof generated from the same private key used by
`sign`. Consumers must validate it through
`forge::crypto::bls::verify_proof_of_possession` before accepting a key into an
aggregate-signature policy.

This keeps key custody inside the plugin while allowing a downstream chain to
persist its own policy and proof records.

## Portability Hardening

BLS text parsers now validate prefixes with bounded `starts_with` checks, so a
short malformed value cannot cause an out-of-range iterator read.

The BLS signer API and Savanna finality module also include their own fixed-width
integer declarations. Consumers no longer depend on an incidental prior import
for `std::uint8_t`, `std::uint32_t` or `std::uint64_t`.

## Compatibility

Existing `keys` configuration and `forge.plugins.crypto.signer` API v2 are
unchanged. Applications that do not configure `bls-keys` do not publish or
receive BLS key material through the asymmetric API.

The new BLS contract is additive and has version `1.0`.
